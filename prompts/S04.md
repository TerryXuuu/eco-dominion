## Acceptance
Local integrated platform passes observed core journeys, engine tests, integration tests, typecheck and production build; any unresolved critical issue blocks acceptance; source and ledgers are committed with no claimed deployment.

## Validation
Automated target: node --test tests/session-S04.test.mjs. Create this test with meaningful assertions against this block's actual behavior; missing tests must fail acceptance. Preserve node --test tests/engine.test.mjs tests/invariants.test.mjs. App blocks also require typecheck/build and relevant real-database/browser checks; retain their observed logs. Manual: Repeat one complete journey with two independent browsers; confirm blocked/suspended permissions, replay, reconnect and responsive controls.

## Evidence and automatic handoff
Save actual check logs and browser/manual observations in this session's evidence directory. acceptance.json requires the active session ID, architecture_version=2.3, summary, changed_files, automated_checks and manual_checks (each status=pass and an existing repository-relative evidence file), blockers=[]. Never fabricate human approval or evidence. If browser automation is available, gather observed journeys directly; if it is unavailable, pause for actual observations.

Do not edit orchestration code, frozen architecture, tests merely to weaken gates, or accepted history. Update decisions and co-build log. In IDE mode invoke python tools/auto_run.py finish: it validates evidence, runs checks, creates implementation and audit commits, and activates the next block. End this block at that boundary; the automatic workflow then prepares the next block automatically. In CLI-worker mode do NOT call finish, prepare, run, controller accept, or change state: the parent runner owns handoff and Git commits. Return after saving evidence. On failures save the exact blocker and next action; no forced acceptance. Rollback checkpoints are retained; never reset user work.
