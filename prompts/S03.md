# S03 — Community and user management

Budget: four hours. Architecture 2.3. This is one broad session; keep implementation details within it. Environment setup and final deployment are excluded.

## Objective and implementation sequence
Implement a paginated text community feed, posts/comments/likes, profiles, friends/follows/blocks, in-app notifications, reports, moderator hide/suspend actions and audit records. Apply server-side ownership, visibility and role checks across community and game invitations. Use one coherent UI and plain text content; skip media uploads.

## Context and constraints
Read AGENTS.md, TASKS.md, docs/ARCHITECTURE_FREEZE.md, docs/API_AND_DATAFLOW.md and the applicable rules/card audit. Inspect existing work and evidence. Follow architecture 2.3 with one Next.js app, Neon Auth and Neon PostgreSQL. Do not rebuild the reference engine needlessly. Verify current official SDK documentation and pin compatible dependency versions. Human rules decisions are not AI-generated approvals.

## Acceptance
Users interact through persistent feed and relationships; blocks/visibility respected; reports reach moderators; only authorized moderators can act; suspended users cannot mutate the platform.

## Validation
Automated target: node --test tests/session-S03.test.mjs. Create this test with meaningful assertions against this block's actual behavior; missing tests must fail acceptance. Preserve node --test tests/engine.test.mjs tests/invariants.test.mjs. App blocks also require typecheck/build and relevant real-database/browser checks; retain their observed logs. Manual: Create/comment/like with two users, then block; attempt cross-user edits and ordinary-user moderation; resolve a report and inspect the audit trail.
