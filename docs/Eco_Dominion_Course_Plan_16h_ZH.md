# Eco Dominion 16 小时课程计划

中文项目名：生态霸权。通过四个较大的开发单元构建注册、在线双人 PvP 与社区的核心平台。使用 Cursor、Neon、GitHub；Vercel 为后续托管目标。环境搭建和最终部署均不计入 16 小时。

## 一 课程成果与工作方式

完成后的目标是：两名真实注册用户能进入房间，按照已确认规则完成全卡池对局，断线后恢复状态，查看战绩与回放，并参与具备权限和审核能力的社区。原始规则中的四区域、六阶段、公共牌库和全部 36 种卡牌保持完整。

默认自动运行。在 Cursor 中以 eco-dominion 为项目根目录，发送 KICKOFF.md 中的一次启动指令；Agent 自动读取当前提示词、保存检查点、实施并验证，通过后自动提交代码与更新 TASKS，再进入下一开发单元。无需手动复制 S01 至 S04 提示词，也无需手动执行常规提交或状态更新。每个单元仍保持独立验收与提交边界，不再细分大量课次。参考引擎、卡牌目录、规则冲突文件、Git 工作流和 TASKS 状态系统沿用已有项目包。每个单元开始保存回滚检查点，结束保存真实证据和实现提交，通过验收后再激活下一个单元。

| 单元 | 时间 | 主要成果 |
|---|---:|---|
| S01 账户与规则基础 | 4 小时 | 确认数字规则；应用、认证、资料与数据库接入 |
| S02 在线 PvP | 4 小时 | 双账户完整对局、持久状态、重连、结果与基础排名 |
| S03 社区与用户管理 | 4 小时 | 动态与互动、关系与屏蔽、举报审核与审计 |
| S04 集成验证与交接 | 4 小时 | 完整流程验证、关键缺陷修复、本地构建和源码交接 |
| 合计 | 16 小时 | 四个开发单元，无额外环境或部署课时 |

16 小时为开发预算；一个单元满 4 小时不等于自动完成。未通过时记录阻塞、实际耗时与下一步，保留当前单元状态。如需更多时间，明确报告超出 16 小时，不将追加工作隐藏在“验收”或“准备”名下。

## 二 开课前条件

Cursor 已可使用且具有足够的实际 Agent 额度；Node、Git 和仓库访问已准备；Neon 数据库与认证配置、必要邮件能力及环境密钥已由你准备。课程不包含工具安装、订阅购买、云项目开通或最终 Vercel 发布。SDK 集成、数据库迁移代码和应用本身的构建仍计入 S01 至 S04。

使用已有包中的 eco-dominion 作为 Cursor 项目根目录，先读 AGENTS.md、TASKS.md、当前状态和相应 prompts/Sxx.md。默认在 Cursor IDE Agent 中发送 KICKOFF.md 中的启动指令。若需要无人值守、每个单元启动独立 Agent 进程，可使用 python tools/auto_run.py run；此路线要求 Cursor CLI 已安装并登录，控制器自动发现 agent 或 cursor-agent，不需要手动配置 ECO_AI_COMMAND。CLI 安装与登录仍为课前条件，不增加课程小时数。IDE 对话受到 Cursor 自身额度、权限和上下文限制，中断后再次发送 KICKOFF.md 中的启动指令 恢复。负责人在 S01 中真实确认数字规则；AI 不得代签批准。

## 三 S01 账户与规则基础

**时间：4 小时。** 将原文规则转换为能被服务器唯一判定的已确认版本，同时完成账户和应用的基础链路。

结合手册与卡牌图鉴确认能量起点、每人八回合、胜利检查、永久惩罚、联动与被动、响应窗口等问题。保留原始文件，记录确认项与尚未确认的阻塞；已确认规则绑定版本。复用现有引擎和卡牌目录，在单一 Next.js 应用内接入 Neon Auth 的注册、登录、退出与找回账户，实现个人资料和权限。将认证身份映射到内部用户，执行并验证数据库迁移。

**关键学习内容：** 把自然语言规则变成状态与约束；区分身份认证和业务授权；理解用户、对局和社区数据的关联。

**验收：** 两个账户分别注册登录；退出后受保护功能不可访问；账户恢复流程可验证；用户不能修改他人资料。数据库实际迁移成功，规则批准真实记录，应用构建通过。若邮件或规则批准受阻，保存真实阻塞，不编造成功记录。

**交付：** 应用入口、认证接入、资料界面、迁移文件、规则版本与批准记录、测试日志，以及以 S01 开头的实现提交。

## 四 S02 在线 PvP

**时间：4 小时。** 打通两名已认证用户的完整游戏链路，而不是只演示本地选择双方席位。

完成私人房间、休闲匹配、服务器命令接口与对局界面。界面呈现四区域、六阶段、能量、稳定度、手牌与合法目标，并支持强制选择和超限弃牌。以数据库事务处理锁定、版本校验和指令去重；通过席位过滤返回对局状态。采用版本轮询，断线重连时从数据库恢复。加入认输、持久截止时间、结果、基础排名、战绩与回放。

**关键学习内容：** 服务端权威状态、事务一致性、重复请求幂等、隐藏信息保护，以及确定性回放。

**验收：** 两个独立浏览器完成一场完整对局。断开一方后重连恢复正确状态；并发重复请求只执行一次；旧版本请求被拒绝；浏览器网络数据不暴露对手手牌、牌库顺序或随机种子。结果和排名仅更新一次。全部卡牌效果有回归覆盖，不以一个成功对局替代全卡池检查。

**交付：** 对局服务、房间与匹配、棋盘界面、持久指令和回放、排名结果、实际数据库和双浏览器证据，以及 S02 实现提交。

## 五 S03 社区与用户管理

**时间：4 小时。** 让账户既能参与对局，也能持续交流，并建立可用的内容治理链路。

实现可分页文字动态、评论、点赞、个人主页、好友、关注、屏蔽和站内通知。建立举报、管理员隐藏内容或停用账户、审计记录。所有修改在服务端校验身份、所有权、可见性与角色；屏蔽规则同时作用于社区内容和游戏邀请，停用用户不能继续写入平台。采用文字内容和默认头像，不安排图片上传工程。

**关键学习内容：** 数据关系、分页、资源所有权、角色权限与审核留痕。

**验收：** 两名用户创建内容并互动；点赞重复请求不会重复累计；屏蔽和隐私规则生效。普通用户不能编辑他人内容或执行审核；管理员能够处理举报，审核记录可查询；被停用账户不能发布内容或执行受限制的游戏操作。

**交付：** 社区和个人主页、关系与通知、举报审核界面、权限测试与实际观察证据，以及 S03 实现提交。

## 六 S04 集成验证与源码交接

**时间：4 小时。** 验证整个系统，并把剩余时间用于修复影响核心功能的缺陷。本单元不发布到 Vercel。

沿着“注册登录、完善资料、进入房间、完成对局、查看结果、社区互动、举报审核”的路径执行双账户测试。集中检查认证隔离、越权、重复与并发请求、重连、回放确定性、停用和屏蔽，以及移动端操作、加载和错误反馈。运行规则引擎回归、应用集成测试、类型检查和本地生产构建。

**关键学习内容：** 以可观察证据验收，判断测试覆盖的能力边界，使用 Git 和状态记录完成可靠交接。

**验收：** 核心完整流程通过；关键权限、隐私或一致性缺陷未解决时不得通过。构建、类型检查和必需测试成功，原始文档与卡牌目录完整，README、运行说明、已知限制和开发状态一致。不得将本地构建写成“已上线”。

**交付：** 最终源码与锁文件、迁移、测试证据、已知限制、环境变量名称清单及提交历史。清单不包含真实密钥；最后保留 S04 实现提交和验收状态提交。

## 七 暂停恢复与最终边界

自动控制器在缺少证据、检查失败或真实决策缺失时记录当前单元、Git 修改、回滚点、失败原因与下一步，并保留未提交修改。主动暂停使用 python tools/auto_run.py pause，恢复使用 resume 后再次发送 KICKOFF.md 中的启动指令 或 run；继续同一单元，不重置已验收历史或旧检查点。暂停后计时停止，恢复时保留已用预算；追加小时必须明确记录为超时，不能伪装为仍在 16 小时内完成。每个单元的实现提交与验收状态提交分别保留，未通过的单元不能提前标记完成。

课程范围覆盖账户、完整规则对局和基础社区。高级美术、图片上传、自定义多因素认证、复杂赛事、大规模压测及长期运营验证不纳入本次预算。无人访问时自动执行超时结算所需的调度服务也不计入当前方案；现有方案在读取或操作时检查截止时间。

最终 Vercel 部署、域名、生产配置与线上验证由你后续完成，均不计入这 16 小时。本课程的结项依据是已观察的核心功能与本地测试证据，不是运行小时数。

## 八 原始需求对应关系

玩法依据两份 v1.0 原始文档：四区域和六阶段来自规则手册；完整卡池、牌库数量和效果来自卡牌图鉴。平台的注册、对局服务和社区来自你的新增需求。课程使用原始中文名称“生态霸权”，保留 Eco Dominion 英文标题；卡牌和机制名称沿用原文，不重新命名。

## 自动运行验证

架构 2.3 以自动模式为默认。当前控制器通过 9 项隔离自动编排测试与 5 项既有工作流测试，包括自动读取、独立提交、下一单元、失败阻塞、工作保留、预算和恢复。测试使用临时目录中的模拟 Agent，不代表已在你的 Cursor 登录账户上实际运行。已有规则引擎回归仍须通过；四个应用实现单元仍为未验收状态。真实规则批准、必要凭据和实际浏览器证据不能由自动化伪造。
