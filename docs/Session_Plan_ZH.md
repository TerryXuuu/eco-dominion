# 生态霸权：16 小时开发计划

使用 Cursor IDE Agent、GitHub、Next.js、Neon PostgreSQL 与 Neon Auth；Vercel 为后续托管目标。环境搭建和最终部署不计入本计划，也不安排对应开发课时。

| 开发单元 | 时间 | 核心成果 |
|---|---:|---|
| S01：账户、规则与应用基础 | 4 小时 | 确认数字规则；接入注册、登录、退出、找回账户；实现个人资料与权限；验证数据库迁移。 |
| S02：在线 PvP | 4 小时 | 私人房间与休闲匹配；服务端权威裁判；完整卡牌操作；重连、认输、结果、基础排名与回放。 |
| S03：社区与用户管理 | 4 小时 | 动态、评论、点赞、好友、关注、屏蔽、站内通知、举报、审核与审计记录。 |
| S04：集成验证、修复与交接 | 4 小时 | 双账户完整流程；并发与隐私测试；界面修复；类型检查、测试与本地生产构建；整理提交记录。 |
| **合计** | **16 小时** | **四个较大的开发单元，不再细分成大量课次。** |

每个单元使用一个 Cursor Agent 对话；具体实现步骤在单元内部完成。以 eco-dominion 为项目根目录，先读 AGENTS.md、TASKS.md 和当前 prompts/Sxx.md。保留已提供的规则引擎与全部 36 种卡牌，避免重新实现已有代码。

每个单元开始前保存 Git 回滚检查点；结束时保存真实测试日志与手动观察证据，提交实现，再由会话控制器更新 TASKS 状态。四小时结束不等于验收通过：未完成或失败时记录阻塞原因，继续同一单元；如实际超时，应明确报告，不能声称仍在 16 小时内完成。

前提：Cursor 可用额度、Node/Git、GitHub 仓库、Neon 数据库与 Auth 配置、所需邮件服务和密钥已经准备好。S01 的应用接入与数据库代码仍在开发预算内。S04 的本地构建不是线上发布。

架构为一个 Next.js 应用，通过已认证 HTTP 命令和版本轮询同步回合制游戏。Neon 保存权威状态；事务内锁定对局、校验身份和版本、防止重复执行。不得向对手泄露手牌、牌堆或随机种子。无独立游戏服务器或 Redis 服务。

本次目标保留账户、完整游戏与社区的核心功能。高级美术、图片上传、自定义 MFA、复杂赛季或赛事、大规模性能认证及运营强化不属于此次压缩实现范围。16 小时是积极的开发目标，不是生产就绪保证。数字规则仍为待批准草案，必须由项目负责人真实确认，AI 不得伪造批准。

英文和中文的详细规则冲突文件仍包含在包内。最终 Vercel 发布由你后续完成。
