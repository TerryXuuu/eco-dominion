# Rules audit and proposed digital rulings

Status: DRAFT FOR OWNER REVIEW. The project is technically feasible; the source is not yet a complete executable specification. S01 must record explicit owner approval or amendments in decisions/OWNER_RULES_APPROVAL.md. The provided engine implements the draft below for experimentation. Preserve v1.0 source files unchanged. Each accepted amendment receives a ruleset ID, content hash and regression fixture; existing matches keep their original ruleset.

| ID | Source issue | Draft resolution and required fixture |
|---|---|---|
| R01 | “Before end of turn 8” versus “both finish 8 turns” | Eight personal turns per player, alternating, maximum 16 settlements. Domination checked at settlement, including last turn; otherwise final scoring after both turn counters reach 8. |
| R02 | Starts at energy maximum 1 then first refresh adds 1, but 8-cost legends said playable on turn 8 | Initialize maximum 0; first refresh yields 1. Personal turn t gives t energy. Maximum 10 retained but never reached in ordinary eight-turn play. |
| R03 | Opening player skips first draw; second first draw unspecified | First player's first turn draws 0; second player's first turn draws 2; all later turns draw 2. Preserve 5-card opening hands. Test advantage rather than assume compensation succeeds. |
| R04 | Event cadence could mean one per shared round or personal turn | One event per personal turn, 16 maximum, active-player then opponent choice order. This materially affects balance. |
| R05 | Hand overflow choice, timing and simultaneous draws unspecified | Draw-phase overflow resolved before event reveal. Enter/spell overflow immediately blocks further actions. Both-player event overflow resolved opponent then active player in this reference engine because queue prepends; production must freeze that order explicitly. No client auto-discard. |
| R06 | No controller defined before first settlement yet many cards require control | Target legality uses current derived power, not stale last-round owner. Ties neutral; zero versus zero neutral. Refresh beaver uses previous recorded settlement owner. |
| R07 | “Permanent power only increases” conflicts with permanent quarter penalty | Keep immutable species base power plus region-side cumulative penalty ledger. Migration moves species, not region penalty. Aggregate power clamped at 0. |
| R08 | Penalty then victory might change controller | At settlement compute owners with synergies already disabled in nonpositive regions; active-player reserve payout uses pre-penalty owners; apply penalty once per controlled region; recompute owners for victory. Both sides can incur penalty, only active side gets ordinary income. |
| R09 | Immediate victory wording versus six-phase check | No mid-deployment or mid-event win. Only settlement checks domination. |
| R10 | Final permanent score and region control under temporary effects unclear | Recompute final control and score without temporary modifiers, retaining enabled continuous passives, synergies and permanent penalties. Tied regions contribute nothing. Do not run another penalty. |
| R11 | Deer gives passive stability and lizard synergy gives stability but how often? | Deer contributes +2 while present. Each lizard contributes +3 while same-owner fox present and synergy enabled. Both recompute on migration; never add each refresh. Deer is intrinsic stability; lizard uses base plus deer >0 activation to avoid a recursive threshold. |
| R12 | Duplicate synergies and aura stacking unspecified | Pair presence is Boolean per recipient, not multiplication by partner count. Each aura source stacks additively and includes itself where “all your species” is written. |
| R13 | Which passive effects stop at nonpositive stability? | Power auras, bison scaling and synergies disabled; deer intrinsic stability remains. Beaver refresh income remains based on previous control. All enter effects remain once-only. This is a proposed interpretation of card-book commentary, not unambiguous original text. |
| R14 | Temporary buffs follow creatures or regions after migration? | Spell buffs/debuffs attach to species UID present at cast time and move with it. Heat is dynamic cost filter; invasion +4 is region-side aggregate. New species do not inherit old targeted buffs. |
| R15 | Can opposing player react? Manual says cannot, commentary suggests reactive counters | No interrupt stack. Each player acts only on their own deployment/tactics phase; exceptions are forced shared-event/overflow choices. Opponent cannot cast to stop current-turn domination. Remove misleading counter-window claims from digital help. |
| R16 | Snake immune to interference targeting regions or players? | Immunity only protects snake from unit-affecting interference (currently veil); once per snake per personal turn while ray synergy enabled. It does not block region stability changes, resource theft, or disabling region synergy. |
| R17 | Break “enemy synergies” versus all passives | Break suppresses pair synergies only, not general power auras. Lizard conditional stability removed; deer intrinsic stability retained. |
| R18 | Bison enter target absent and veil “enemy region” unclear | Bison requires enemy-controlled region when any exists, otherwise enter effect has no target. Veil requires enemy species present, whether or not enemy controls it. Break requires currently enabled enemy pair. |
| R19 | Terrain destruction “next turn region reserve” scope | Blocks enemy's next water beaver refresh income and next ordinary settlement income from target region, expires after that settlement. Does not block reserve gained by enter/charge/revival effects. |
| R20 | Shared event decisions and tie behavior | Rest skips players with no controlled regions. Migration optional, one species per player, no enter effect and no draw. Invasion target selected by active player; more species gets +4 aggregate, tied count gets zero. |
| R21 | Nature balance with continuous stability offsets | Set effective nonpositive stability to zero by adjusting base stability; keep permanent species offsets. |
| R22 | Example spends 5 when it has 4 | With reserve 0, deer then fortify is illegal. Correct example: energy 4 and reserve 1, deer consumes 2; fortify consumes reserve 1 plus energy 2. Never permit energy -1. |
| R23 | Deployed species allegedly all enter discard when played | Deployed species remain on board. Spells enter shared main discard after play; forced discarded species enter discard. No removal and no board slot limit. |
| R24 | Deck cannot reshuffle if no cards remain in discard | Attempt draw, recycle discard if available, otherwise draw fewer cards. No deck-out loss. Costs/turn cap prevent endless draw loops. |
| R25 | Random discard and shuffles lack digital determinism | Production cryptographic random seed generated on server, deterministic stream stored privately with state and replay. Test PRNG in starter is reproducible, not a production fairness mechanism. |
| R26 | Disconnect, inactivity and concession not defined | Production transport policy: 90-second personal-turn action budget and 30-second forced-choice budget; reconnect doesn't reset deadline. Deadline expires to deterministic discard/skip/pass policy; 3 consecutive timeouts cause forfeit, concession allowed via separate authenticated lifecycle endpoint even off turn. Service outage voids ranked outcomes. All times are product choices to approve in S01. |

Do not infer that these resolutions prove balance. They make a testable draft. The exact owner approval artifact must cite each R-ID and list exceptions; never have an AI sign it on the owner's behalf.
